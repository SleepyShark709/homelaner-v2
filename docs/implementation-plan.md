# UNDEFEATED 浏览器重建执行方案

项目位于 E:/undefeated-web，使用 Babylon.js、TypeScript、Vite。目标为桌面浏览器本机运行，先保留原角色与原玩法，再按用户要求逐步改造。优先支持键鼠；手机与多人联机不列入当前验收。

## 技术路线

现有安装包是 UE 4.27 的发行成品。不能把 Windows exe 或 cooked 蓝图直接上传到网页运行，也不能从这些包恢复一份完整的 UE 源工程。当前选择将可转换的原网格、骨架、动画和贴图送入 glTF；依据已恢复的蓝图逻辑，在 TypeScript 中重新实现控制器、状态机和游戏规则。

浏览器在本机渲染与运算，无需为每个玩家租用云端 GPU。开发工具和导出数据位于本项目；原游戏安装只读。原资产派生文件暂只保存在本机，未发布网站或上传仓库。

Babylon.js 负责场景、相机、模型与骨骼动画。物理候选为 Havok，接入前先验证角色胶囊、楼体碰撞和高速飞行穿透；此版本尚未安装物理引擎。状态、战斗命中与计分由独立 TypeScript 模块管理，不把规则绑定在某个角色外观上。

## 阶段 00：资产与动画链路

交付可运行的资产实验室及可复现转换脚本。核对原主角网格、93关节蒙皮、4段原版动画、头发/墨镜、建筑和车辆样本。记录材质简化、附件装配及缺失的原特效。

验收：所有本地资源引用有效；关节绑定与时间序列通过数值检查；浏览器可显示模型、切换动画及查看骨架。此阶段不是可玩的游戏。

## 阶段 01：原版 Web 基线

按以下子阶段推进，每一步保留可运行版本：

1. **一个原版街区与可控角色**：解析地图 actor 位置/旋转/缩放，按原布局装配；接入步行、跳跃、飞行、加速、第三人称相机及碰撞。暂不以程序生成方块城市作为原地图完成证明。
2. **原角色完整装配与动作**：头发、眼镜、特效挂点；恢复地面/空中/冲刺/攻击状态、动作切换、命中事件。角色移动由控制器负责，现已导出的4段动作根骨位移均为零。
3. **攻击与人车**：普通攻击、右键远攻、原版技能；车辆道路样条、避障与回收；市民路径/避让/逃跑与对象池。原版路人并没有通用生命/死亡逻辑，不能仅改一个阵营开关就实现自由攻击。
4. **城市与游戏流程**：按实际资源逐区加载，恢复城市状态、事件、挑战、Boss、菜单和存档；将缺失系统列出，并与原版行为对照。
5. **性能与体验**：贴图降采样/压缩、LOD、实例化、视距裁剪、按区加载、对象池；验证高速飞行、落地、连续攻击、模型加载失败和切出窗口。

完成原版基线的标准是能走通约定的原版游玩流程，而不是出现一个可动角色。先记录本机帧时间、内存、下载体积，再确定量化性能门槛；不预先承诺未测过的设备帧率。

## 阶段 02：按住 E 触发热视线

保留原右键远攻，新增 E 直接进入原 OpticRay 对应行为，松开停止。原版 E 占用上升操作，因此改为飞行时 Space 上升、Ctrl 下降；地面 Space 跳跃。

原逻辑参考：从眼部挂点发射，瞄准相机前方，射线决定命中，约0.1秒间隔处理效果。Web端重建射线束、命中特效及状态入口。失焦、暂停、重置均释放按键并停止射线。

验收：移动/飞行中可持续瞄准；按住/松开正确；遮挡有效；右键原能力保留；切出窗口不会卡住持续发射。

## 阶段 03：自由破坏与无惩罚模式

增加统一的可受击接口：市民、车辆、指定道具均可被普通攻击或热视线影响。车辆复用原爆炸/隐藏/回收机制；市民新增受击、倒地及回收行为。材质破坏与模型碎片按资产能力逐项实现。

自由模式中关闭玩家伤害/死亡、硬直/击退/眩晕等控制剥夺、负面计分、降级降速、城市血量触发失败、能力资源限制和强制中断自由游玩的规则。保留墙地碰撞、地图边界与主动重置，避免无惩罚被误实现为掉出地图或完全穿墙。原版规则保留为回归对照。

整栋建筑任意切割与结构倒塌属于另一个系统，目前默认只包含已指定的可破坏对象；若扩大到整城建筑，另设几何破碎与物理预算阶段。

验收：攻击人车有效、无负面计分或强制失败；持续飞行/战斗不降速或失控；对象回收稳定；重置后恢复完整场景。

## 阶段 04：祖国人外观

目标只是更换外观，不要求沿用祖国人仓库的骨架和动作。优先保留已验证的 UNDEFEATED 骨架、原动作和控制器，把祖国人的网格适配到它。

流程：检查模型格式/比例/材质 → 对齐参考姿势 → 转移或重新制作蒙皮权重 → 修正肩、肘、髋、膝与手指变形 → 验证全部原动作 → 调整眼部/手部特效挂点 → 单独处理披风。

因此，**可能需要重新蒙皮，但无需从零建立全部骨骼或重做整套动画**。是否可以自动转移、需要多少人工修正，要等模型本身加载检查后确定。当前没有承诺祖国人模型能直接替换文件。

## 如何验收与管理风险

每阶段交付本地运行入口、实现/未实现清单、对应来源和验证结果。将静态资产默认值、已恢复的蓝图控制流、实际运行观察分开记录。自定义 C++ 部分如无法恢复，依据可验证行为补实现并说明差异。

最主要的不确定项是整张地图布局恢复、UE材质/特效复刻、完整攻击动画事件、Boss流程和城市性能。完成一个原街区后再估算剩余工作量；当前资产导出结果不能证明整张城市可无损自动转换。
